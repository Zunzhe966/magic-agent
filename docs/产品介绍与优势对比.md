# 尊者魔法代理：产品介绍与优势对比

> 面向：想了解「这个软件跟现有代理软件比，到底强在哪、缺在哪」的人。
> 态度：只讲事实，不吹嘘，也如实写清不足。

---

## 一、一句话定位

**「按软件精确分流 + 云服务器控制台 + AI 可操控」三合一的 macOS 代理工具。**

现有代理软件解决的是「怎么连上节点」；本软件解决的是「**谁**走代理、**谁**直连、以及**连上之后怎么顺手把服务器也管了**」。

---

## 二、和现有代理软件的对比

| 维度 | Clash Verge / FlClash / Surge | 尊者魔法代理 |
|---|---|---|
| 分流粒度 | 域名/IP 规则为主，全局 TUN 接管 | **按软件（进程）精确分流**，每个 App 独立设置 |
| 国内外判断 | 软件自动判断（`GEOIP,CN` 等），用户不可见 | **双路显式出口**：直连 7892 / 代理 7893，决策权交给用户/AI |
| 服务器管理 | 无（需另开 FinalShell 等） | **内置 SSH 终端 + 一键探针 + 快捷命令** |
| AI 集成 | 无 | **23 个 MCP 工具**，AI 可自主控制代理和服务器 |
| 资源占用 | Electron 体积 80~200MB、内存 120~400MB | **Tauri 体积 2~10MB、内存 30~50MB** |
| 隐私/安全 | 参差不齐 | **DNS 全加密 + 配置 0600 + API 带 secret + Keychain 存密钥** |

### 真正的差异化优势（按重要程度排序）

1. **按软件分流是产品核心，不是附属功能**。现有工具也能靠进程规则（Clash 的 `PROCESS-NAME`）做，但界面里藏得深、难配置；本软件把它做成第一等公民——扫描出 App 清单，勾选即可。
2. **「上网 + 管服务器」合一**。传统上这是两个软件的事；本软件一次装好，代理和服务器管理共享同一套节点配置、同一套密钥存储。
3. **AI 原生可操控**。通过 MCP 协议，AI 助手能拿到真实的「双路路况」数据（`probe_route` 实测延迟/吞吐）后自己决定走哪条路，而不是猜「这是国内还是国外域名」。
4. **轻量**。Tauri 架构天然适合 24 小时常驻后台的代理工具，Electron 在这个场景是硬伤。
5. **协议用最严格档**。VLESS + Reality + XTLS Vision，抗主动探测；DNS 全加密、密钥进 Keychain，隐私加固做足。

### 如实的不足（当前阶段的短板）

1. **仅 macOS**。跨平台（Windows/Linux）还没做；Surge 等有 iOS 端，本软件目前没有移动端。
2. **按软件分流的「绝对性」有边界**。系统代理只对遵守系统代理的软件生效；Telegram 默认直连、部分游戏/命令行工具无法被系统代理约束，需要 TUN 或额外手段才能 100% 强制。
3. **节点协议单一**。当前主要面向 VLESS + Reality；SS / Trojan / Hysteria2 等协议的支持不如 Clash 生态齐全（内核是 mihomo 理论上支持，但界面和订阅解析还没全覆盖）。
4. **生态和社区**。Clash 生态有海量规则订阅、现成配置模板；本软件一切从零，规则库、文档、社区都还在积累。
5. **单机定位**。没有多设备同步、没有云端配置托管；配置存本地。

## 三、协议说明（为什么选最严格档）

节点使用 **VLESS + Reality + XTLS Vision**：

```
encryption: none            # VLESS 内建认证，无需二次加密
security: reality           # 无证书、握手即伪装正常 TLS 流量
flow: xtls-rprx-vision      # 流量特征伪装，抗主动探测
client-fingerprint: chrome  # 指纹伪装成 Chrome
```

配套隐私加固：DNS 全加密（DoH + DoT）、`mihomo.yaml` 权限 `0600`、控制 API 强制 secret、SSH 密钥进 macOS Keychain。

> 这一档是当前 VLESS 体系里隐蔽性最高、抗封锁能力最强的组合，也是「最严格」的含义。

## 四、适合谁

- 需要「某些软件走代理、某些走直连」的精细控制，受够了全局代理混乱的人。
- 既有上网需求、又有自建云服务器需要频繁管理的人。
- 希望 AI 助手能自动、安全地控制网络和服务器的人。
- 看重轻量、隐私、不想要一个几百 MB 常驻后台的人。

## 五、还不适合谁

- 需要 Windows/Linux/移动端全平台的人。
- 依赖大量现成规则订阅、多协议混用的重度 Clash 用户。
- 需要多设备配置同步的团队场景。
