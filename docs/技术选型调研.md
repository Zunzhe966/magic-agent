## 2. "从零写"的边界（必须先和你对齐这一条）

"从零写"我理解为**产品代码 100% 自己写**。但有四类东西属于"基础设施工具"，不等于抄产品：

| 类别 | 具体物 | 为什么算工具而不是"抄" | 类比 |
|---|---|---|---|
| 窗口框架 | Tauri 2 | 提供窗口、IPC、托盘、菜单，不实现任何代理/服务器逻辑 | 用 Rust 语言本身 |
| 代理引擎 | mihomo（外部进程） | 只做"把流量转发到 VLESS 节点"这一件事，作为独立二进制启动和调用，**一行代码都不进工程** | 像产品调用系统的 `ssh` 命令 |
| 协议实现 | VLESS + Reality | 不重写。这是别人已验证的加密协议，自己写 = 几周工作量 + 高概率的弱安全实现，反而危险 | 用 openssl 而不是自己实现 AEAD |
| 终端组件 | xterm.js | 只负责把文字漂亮地画出来，PTY/SSH 会话逻辑全由我们自己写 | 用富文本组件 |

**真正自己写的（本产品的全部差异化价值）**：
按软件分流引擎、App 扫描/策略存储、mihomo 生命周期管理与配置动态生成、系统代理读写与冲突检测、SSH 连接管理（密钥、Keychain 加密存储）、快捷命令、状态/日志/界面全部。

👉 **需要你确认：mihomo 作为外部引擎进程（不抄代码、独立调用）是否接受？** 如果不接受，就必须自己用 Rust 实现 VLESS/Reality 协议客户端，工期变成按周计，我不建议。

## 3. 桌面壳调研：Tauri 2 vs Electron vs 原生 Swift

| 维度 | Tauri 2（2.11 线，2026 现状） | Electron 34 | 原生 Swift/SwiftUI |
|---|---|---|---|
| 安装包体积 | **2~10 MB** | 80~200 MB | 10~30 MB |
| 空闲内存 | **30~50 MB** | 120~400 MB | 20~60 MB |
| 冷启动 | **< 1s** | 1~3s | 极快 |
| 后端语言 | Rust（一门语言管全部） | Node.js | Swift（前后端两套语言/生态） |
| 常驻托盘、低资源 | ✅ 明显占优（代理工具必须 24h 常驻） | ❌ 架构性硬伤，优化不掉 | ✅ |
| 多开/多会话资源 | 几乎无叠加 | 每开一个窗口叠一份 Chromium | — |
| 安全模型 | 权限白名单制，前端默认什么都做不了 | 需自己加固 renderer | 原生 |
| 跨平台 | Win/mac/Linux + 移动 | Win/mac/Linux | 只有 macOS |
| 主要缺点 | 各平台 WebView 渲染有细微差异（本项目只有 macOS 版，**无影响**） | 重 | 前后端两生态、无法扩展 |

本工具是**要 24 小时常驻后台的轻量工具**（代理开关 + 托盘），Electron 的体积/内存是硬伤；原生 Swift 可行但前后端两套语言生态、且第一版想聚焦业务。**结论：Tauri 2。**

## 4. 后端语言：Rust（配 Tauri 2）

Rust 侧需要干六件事，全部有成熟、纯 Rust、无需编译原生 C 的 crate：

| 职责 | 技术方案 | 说明 |
|---|---|---|
| 管理 mihomo 进程 | `std::process` + 自写守护循环 | 启停、崩溃重启、信号处理，逻辑全自己写 |
| 系统代理读写 | `system- proxy` 操作 `scutil`（自写） | 不依赖 TUN；启动前检测 FlClash/7890 冲突 |
| 扫描全屏 App/进程 | `sysinfo` crate | 拿进程名 + 可执行路径 + bundle id，"按软件"靠路径归组 |
| SSH 客户端 | **russh**（thrussh 的活跃维护分支，2025-08 仍在更新，纯 Rust 异步） | 交互 PTY、命令执行、公钥/密码；备选：调用系统 `ssh` 进程 |
| 密钥安全存储 | `keyring` crate（macOS Keychain） | 密码/私钥不写明文 JSON |
| 配置/策略落盘 | `serde_json`，存 `~/Library/Application Support` | 本地 JSON，不上传 |

（Node/JS 路线：ssh2/keytar 可以，但被 Electron 的内存问题一票否决；Go/Swift：无额外收益。）

## 5. 前端：Vue 3 + Vite

- 界面就 4 个页面（概览 / 应用分流 / 云服务器 / 日志）+ 一个终端输入区，复杂度低。
- **Vue 3 单文件组件**：模板 + 逻辑 + 样式在一个文件里，结构清楚，每个页面都是一个自己写的独立文件，不存在"套别人模板"。
- 备选 React（等价可行）、纯 HTML/JS（更简陋，可维护性差）。你之前第 12 节写的是"HTML/CSS/JS"，Vue 本质就是 HTML 模板 + CSS + JS 的有组织的写法。
- 终端渲染：**xterm.js**（前端组件，见第 2 节边界说明）。
- 打包：Vite，产物就是静态 HTML/JS，由 Tauri 的 WebView 加载。

## 6. 关键技术风险（不夸大，沿用需求文档第 9 节）

1. **进程分流不是 100%**：只有遵守系统代理的软件可控（浏览器、大部分 App ✅）；Telegram/部分游戏/命令行自己直连 → 界面上标"未接管"，不宣称全管。
2. mihomo 的进程规则（PROCESS-REGEX）在 macOS 上实测验证 Chrome/Safari 两条线，作为验收标准。
3. FlClash 同时运行会抢系统代理/端口 → 启动前检测并提示。
4. SSH 私钥/密码只进 Keychain，配置 JSON 里不留明文。
5. "自动"策略用真实 DNS 解析，不开 fake-ip。

## 7. 推荐方案（一句话）

**Tauri 2（窗口壳）+ Rust（后端，Rust 单语言）+ Vue 3/Vite（前端，自己写代码）+ mihomo 外部进程（引擎，只调用不抄码）+ russh（SSH）+ Keychain（密钥）。** mihomo 内核建议直接升级到当前最新版 **v1.19.29**（2026-07 发布）。
