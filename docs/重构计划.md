# 重构计划 · 从「魔法代理」到「网络管理」（一键归序）

> 状态：**规划中**（2026-09-23 制定）。设计立场见 `docs/设计.md`，红线见 `CONTRACT.md`。
> 本计划是功能重构的唯一路线文档；每阶段完成后在 `HISTORY.md` 落账并回写本文档的进度标记。

---

## 总原则

1. **先修信任，再扩能力**：报假账的系统（any_success、口径不一致）不修好，加再多"管理员"功能都是空谈——用户不信你的状态面板，就不会信你的接管。
2. **每步可独立发版**：P0/P1/P2 内部各任务都能单独走完 `release.sh` 闭环，不做一次性大重写。
3. **双引擎一致性不破**：任何行为改动必须 Rust + MCP 两侧同步（`check_parity.py` 守门），直到 P2 收敛为单引擎。
4. **改名最后做**：产品更名「网络管理」放在 P2 末（功能配得上名字时），避免"名字叫了、能力没到"的反噬。Bundle ID `com.magic.agent` 保持不动（Keychain/sudoers/更新签名都绑它，改 ID 代价极高且无用户价值）。

## P0 · 修信任（预计最先做，全部是缺陷修复，无新功能）

### P0-1 system_proxy 逐服务对账 ✅已完成（2026-09-23）

- 问题：`set_system_proxy` 任一服务成功即返回成功；`status()` 读 scutil 全局视图与写入侧口径不一。
- 实现：`verify_system_proxy` 逐服务 `-getwebproxy/-getsecurewebproxystate/-getsocksfirewallproxystate` 读回；`set` 返回 `{enabled, services:[{service,httpOn,httpsOn,socksOn,errors}], allOk, mismatched}`；部分失败 UI warn toast 点名服务；Rust 侧全部 13 个调用点接入 `log_proxy_set_result` 对账日志（消灭 `let _ =` 静默）。MCP `set_system_proxy` 返回同一结构、`status` 增加 `verify:true` 可选对账（默认关，避免轮询放大开销）。附带揪出并修复 `parse_port` 潜伏 bug：scutil 的 `HTTPPort : 7891` 带前导空格，旧解析恒失败导致端口字段永远为 0（P0-4 自愈依赖此值）。
- 验收：Rust 4 项单测（含序列化契约与部分失败可见性）+ Python 4 项 mock 回归（"3 成功 1 失败"如实点名、写失败以读回为准、读回异常点名）全部通过。

### P0-2 listener 回环钉死 ✅已完成（2026-09-23）

- 双引擎 listeners 全部显式 `listen: 127.0.0.1`，Rust 单测锁死；实测依据见设计文档 §七。

### P0-3 root 日志权限 ✅已完成（2026-09-23）

- osascript 路径与 mihomo-ctl.sh 均 `umask 077` + 存量日志 `chmod 600`（含轮转 .old）。

### P0-4 崩溃后自愈补全 ✅已完成（2026-09-23）

- 问题：App 被 kill -9 / 断电时 RunEvent::Exit 不执行，系统代理可能指向死端口。
- 实现：`lib.rs::startup_self_check()` 启动序列（state 构造后同步执行，放后台会与 800ms 后的 cleanup 竞态）——内核未运行且系统代理 HTTP/SOCKS 端口指向本程序 7891/7892/7893 之一时，自动关闭系统代理并写入一次性提示（AppStatus.selfHealNotice，get_status 读取即清空，前端 toast 'warn'）。指向其他端口的系统代理属第三方状态，绝不误关。
- 验收：手工模拟（起内核→kill -9 App→重开）后系统代理自动恢复干净——待装 v0.2.11 后人工回归确认。

### P0-5 发版链路补 Developer ID 签名 + 公证（依赖外部条件）

- 问题：ad-hoc 签名 → Gatekeeper rejected，"网络管理"级软件每次更新都被弹安全警告，信任崩塌。
- 方案：申请 Apple Developer 账号（$99/年）→ `release.sh` 增加 `codesign --sign "Developer ID Application: ..."` + `notarytool staple`。Tauri updater 的 Ed25519 包签名保留不变（两套管的是不同的事）。
- 阻塞项：**需要用户提供开发者账号**，代码侧改动随时可做。

## P1 · 一键归序 MVP（核心新功能）

### P1-1 审计引擎 `auditor.rs`（新模块）

- 输入：无；输出：`NetworkAuditReport { foreign_procs, port_conflicts, stale_routes, dns_state, proxy_ledger_drift, pac_enabled, env_proxy_hints }`。
- 采集命令：`ps`（已有复用）、`lsof -iTCP -sTCP:LISTEN`（带超时，复用 apps.rs 模式）、`route -n get default` + `ifconfig utun*`、`scutil --dns`（只取前 N 行摘要）、逐服务 `networksetup -get*proxy`、`scutil --proxy | grep ProxyAutoConfig`。
- 全部走 `spawn_blocking`（CONTRACT async 红线）；单项采集失败降级为 `unknown`，绝不 panic。
- GUI 入口：Dashboard 新增「网络体检」卡；MCP 新工具 `audit_network`（并入 doctor 的展开项）。

### P1-2 接管账本 `ledger.rs`（新模块）

- 结构：`~/Library/Application Support/magic-agent/ledger.json`（原子写 0600，复用 config.rs::save 模式）。
- 记录时机：每次 start_proxy 前自动快照"将被改变的每一项原值"；stop/还原时逆序回放。
- 字段：`{kind, key, before, after, reversible, ts}`；kind ∈ system_proxy / process / route。
- 冲突策略：存在未结账本时再次开启 → 先提示"上次接管未正常结束，[还原] 或 [接受现状继续]"。

### P1-3 归序流程编排（改造 `start_proxy`）

```
start_proxy:
  audit() → 有混乱源？
    ├─ 快速模式(默认沿用现行为)：清理第三方 → 记账 → 启内核 → 逐服务设系统代理 → verify 回读
    └─ 确认模式(首次/设置页开启)：UI 列出每个混乱源+处置建议 → 用户勾选 → 记账 → 同上
  verify 不通过 → 自动回滚本次接管 + 报错（宁可不启，不留半套秩序）
```

- 现有 `cleanup_foreign_proxies` 保留为快速模式的执行器，逻辑不动（防误杀铁律已在 CONTRACT）。

### P1-4 一键还原 + 漂移巡检

- `restore_network()`：按账本逆序恢复（含停自己内核），GUI 按钮 + MCP 工具 `restore_network`。
- 看门狗扩展：每 5 分钟抽验账本关键项现值（低成本：只跑 verify_system_proxy），漂移则 UI 黄条提示"外部改动 detected，[重新归位]/[接受]"。

## P2 · 架构收敛与更名

### P2-1 MCP 瘦客户端化（消灭双引擎漂移面）

- 现状：`generate_config` 在 Python 侧整份复刻 Rust 逻辑，parity 靠脚本 diff 兜底，每次配置语义变更要改两处（listener 修复即是实例）。
- 方案：MCP 不再生成 YAML；启停/改规则一律经 Rust 侧本地控制口（复用 19091 API + 新增少量 Tauri 命令走 HTTP 桥 `magic-agent-mcp.sh` 已有的 19092 通道反向调用 App）。App 未运行时 MCP 退回旧路径（保底可用），并在 status 里标注 `engine: legacy`。
- 迁移期 `check_parity.py` 保留，直至 legacy 路径删除。

### P2-2 端口占用治理升级

- 7890/1080 等常见端口被竞品占用时：从"拒绝启动/强清"升级为"提议改端口 + 记账 + 还原时收回"。

### P2-3 更名「网络管理」

- 范围：显示名/图标文案/README 标题/MCP serverInfo/UI 顶栏。**不改**：Bundle ID、Keychain SERVICE、sudoers 路径、updater 资产名（历史兼容）。
- `mihomo-ctl.sh` 的 ensure_bin 探测列表追加新 `.app` 名（保留旧名探测）。
- HISTORY 记录更名提交，设计文档 §〇 表撤掉"过渡"字样。

### P2-4 （可选）协议面补齐

- SS/Trojan/Hysteria2 订阅解析与节点表单，视 P1 完成度排期。

## 风险清单

| 风险 | 缓解 |
|---|---|
| 接管第三方被判为恶意行为（杀毒/用户恐慌） | 所有接管动作前列示、后可回滚；README 显著位置讲清"为什么动别的软件" |
| route/dns 采集在不同 macOS 版本输出漂移 | 解析失败降级 unknown，只影响信息完整度不影响主流程 |
| 账本文件损坏导致无法还原 | 复用 config.rs 三层健壮性读取模式（backup_once/recover） |
| MCP 瘦身后 App 未运行场景断崖 | 保留 legacy 路径一个版本周期 + status 明确标注 |
