## 一、这个软件是什么

一句话：**「按软件精确分流 + 云服务器控制台 + AI 可操控」三合一的 macOS 代理工具。**

现有代理软件解决的是「怎么连上节点」；本软件解决的是「**谁**走代理、**谁**直连、以及连上之后怎么顺手把服务器也管了」。

它做两件事：

1. **网络代理**：通过用户自己的云服务器节点上网。
2. **云服务器控制**：在软件里直接连接、查看、操作那台云服务器（SSH 终端、探针、快捷命令）。

它不是又一个 FlClash——它把「按软件分流」和「服务器管理」做成同一个产品的核心体验。

---

## 二、要解决的问题

用户本机原来用 FlClash，感觉「混乱、不智能、全局、一点不好用」：

- 原来是 TUN 全接管 + `MATCH,GLOBAL`，整个电脑几乎所有流量都进代理。
- 例外只能手工猜域名（知乎、京东、银行域名），不是按软件控制。
- Chrome、Safari、QQ、微信、Codex 等全混在同一个代理里，无法精确说「Chrome 走云服务器、Safari 走本机」。

**核心需求：按软件分流。** 把电脑上所有联网软件做成一张清单，每个软件独立指定 走代理 / 直连 / 自动。

## 三、和现有代理软件的对比

| 维度 | Clash Verge / FlClash / Surge | 尊者魔法代理 |
|---|---|---|
| 分流粒度 | 域名/IP 规则为主，全局 TUN 接管 | **按软件（进程）精确分流**，每个 App 独立设置 |
| 国内外判断 | 软件自动判断（`GEOIP,CN` 等），用户不可见 | **双路显式出口**：直连 7892 / 代理 7893，决策权交给用户/AI |
| 服务器管理 | 无（需另开 FinalShell 等） | **内置 SSH 终端 + 一键探针 + 快捷命令** |
| AI 集成 | 无 | **23 个 MCP 工具**，AI 可自主控制代理和服务器 |
| 资源占用 | Electron 体积 80~200MB、内存 120~400MB | **Tauri 体积 2~10MB、内存 30~50MB** |
| 隐私/安全 | 参差不齐 | **DNS 全加密 + 配置 0600 + API 带 secret + Keychain 存密钥** |

### 差异化优势（按重要程度）

1. **按软件分流是产品核心，不是附属功能**。现有工具也能靠进程规则（`PROCESS-NAME`）做，但界面里藏得深、难配置；本软件做成第一等公民——扫描出 App 清单，勾选即可。
2. **「上网 + 管服务器」合一**。传统上是两个软件的事；本软件一次装好，代理和服务器管理共享同一套节点配置、同一套密钥存储。
3. **AI 原生可操控**。通过 MCP 协议，AI 助手能拿到真实的「双路路况」数据（`probe_route` 实测延迟/吞吐）后自己决定走哪条路。
4. **轻量**。Tauri 架构天然适合 24 小时常驻后台的代理工具。
5. **协议用最严格档**。VLESS + Reality + XTLS Vision，抗主动探测；DNS 全加密、密钥进 Keychain。

### 如实的不足

1. **仅 macOS**。跨平台（Windows/Linux）、移动端都还没做。
2. **按软件分流有边界**。系统代理只对遵守系统代理的软件生效；Telegram 默认直连、部分游戏/命令行工具无法被系统代理约束，界面上标「未接管」，不宣称全管。
3. **节点协议以 VLESS + Reality 为主**。SS / Trojan / Hysteria2 等界面和订阅解析还没全覆盖（内核 mihomo 理论上支持）。
4. **生态从零开始**。没有海量规则订阅、现成模板；规则库、文档、社区都在积累。
5. **单机定位**。没有多设备同步、云端配置托管；配置存本地。

## 四、技术选型（为什么这么选）

### 桌面壳：Tauri 2（对比 Electron、原生 Swift）

本工具是要 24 小时常驻后台的轻量工具，Electron 的体积/内存是硬伤；原生 Swift 可行但前后端两套语言生态。**结论：Tauri 2。**

| 维度 | Tauri 2 | Electron | 原生 Swift |
|---|---|---|---|
| 安装包体积 | **2~10 MB** | 80~200 MB | 10~30 MB |
| 空闲内存 | **30~50 MB** | 120~400 MB | 20~60 MB |
| 后端语言 | Rust（一门语言） | Node.js | Swift |
| 常驻托盘/低资源 | ✅ 明显占优 | ❌ 架构性硬伤 | ✅ |

### 后端：Rust

| 职责 | 技术方案 |
|---|---|
| 管理 mihomo 进程 | `std::process` + 自写守护循环（启停、崩溃重启、信号） |
| 系统代理读写 | 操作 `scutil`（自写），不依赖 TUN |
| 扫描 App/进程 | `sysinfo` crate |
| SSH 客户端 | `russh`（纯 Rust 异步） |
| 密钥安全存储 | `keyring` crate（macOS Keychain） |
| 配置落盘 | `serde_json` → `~/Library/Application Support` |

### 前端：Vue 3 + Vite

- 页面少（概览 / 应用分流 / 云服务器 / 域名规则 / 终端），复杂度低。
- Vue 3 单文件组件，模板+逻辑+样式一个文件，每个页面都是自己写的独立文件。
- 终端渲染用 **xterm.js**（只负责画文字，PTY/SSH 逻辑自己写）。

### 「从零写」的边界

产品代码 100% 自己写。但四类属「基础设施工具」，不算抄：

| 类别 | 具体 | 为什么算工具 |
|---|---|---|
| 窗口框架 | Tauri 2 | 提供窗口/IPC/托盘，不实现代理逻辑 |
| 代理引擎 | mihomo（外部进程） | 只做「转发流量到节点」，独立二进制，一行代码不进工程 |
| 协议实现 | VLESS + Reality | 别人已验证的加密协议，自己写反而危险 |
| 终端组件 | xterm.js | 只画文字，会话逻辑自己写 |

**真正自己写的（差异化价值）**：按软件分流引擎、App 扫描/策略存储、mihomo 生命周期管理与配置动态生成、系统代理读写与冲突检测、SSH 连接管理（密钥、Keychain）、快捷命令、状态/日志/界面。

## 五、协议与隐私

节点使用 **VLESS + Reality + XTLS Vision**：

```
encryption: none            # VLESS 内建认证
security: reality           # 无证书，握手伪装正常 TLS
flow: xtls-rprx-vision      # 流量特征伪装，抗主动探测
client-fingerprint: chrome  # 指纹伪装成 Chrome
```

配套隐私加固：DNS 全加密（DoH + DoT）、`mihomo.yaml` 权限 `0600`、控制 API 强制 secret、SSH 密钥进 macOS Keychain。

这是当前 VLESS 体系里隐蔽性最高、抗封锁最强的组合。

## 六、关键技术边界（不夸大）

1. **进程分流不是 100%**：只有遵守系统代理的软件可控；Telegram/部分游戏/命令行自己直连 → 界面标「未接管」。
2. mihomo 的进程规则（PROCESS-REGEX）在 macOS 上实测验证 Chrome/Safari 两条线作为验收标准。
3. 第三方代理（FlClash 等）会抢系统代理/端口 → 启动时自动清理（v0.2.2 起），保证本程序是系统唯一代理。
4. SSH 私钥/密码只进 Keychain，配置 JSON 不留明文。
5. 「自动」策略用真实 DNS 解析，不开 fake-ip。

## 七、适合谁 / 不适合谁

**适合**：
- 需要「某些软件走代理、某些走直连」的精细控制，受够全局代理混乱的人。
- 既有上网需求、又有自建云服务器需要频繁管理的人。
- 希望 AI 助手能自动、安全地控制网络和服务器的人。
- 看重轻量、隐私、不想几百 MB 常驻后台的人。

**暂不适合**：
- 需要 Windows/Linux/移动端全平台的人。
- 依赖大量现成规则订阅、多协议混用的重度 Clash 用户。
- 需要多设备配置同步的团队场景。
